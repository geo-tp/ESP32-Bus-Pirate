Quick reading and writing

Start with I2C EEPROM scan and dump

Confirm the EEPROM family, voltage, address pins and pull-ups before writing. Scan the I2C bus first, then probe the chip size and create a dump before any byte write or erase action.

    Identify the EEPROM family, voltage and address pin configuration.

Example CLI flow
mode i2c
scan
eeprom        # default 0x50 EEPROM shell
eeprom 0x58   # EEPROM shell at a selected address

Use this as a reading and writing preview. In the EEPROM shell, start with Probe/Analyze, then Read bytes or Dump EEPROM before any write or erase action.

Wiring hardware reminders

I2C EEPROM wiring notes before power

Confirm SDA, SCL, pull-ups, address straps, write-protect state and EEPROM voltage before connecting the I2C bus.

Wiring View

Pull-ups

SDA and SCL need pull-ups; modules may already include them.

Address width

The EEPROM shell handles 1-byte vs 2-byte addressing, page size and 24XX/AT24C-style chip probing better than raw register reads.

Writes

Do not write or erase until the shell has identified the chip and you have a verified backup.

Before wiring a module or target chip, check pinout, voltage, ground reference and whether the selected ESP32-S3 board has the required pins free.

What I2C EEPROM is used for

I2C EEPROMs such as 24XX / AT24C-style devices store small configuration blocks, calibration data and board identity information.

Bit Pirate practical value

Why use I2C EEPROM with ESP32 Bit Pirate

ESP32 Bit Pirate provides a safe path from scan to the dedicated I2C EEPROM shell, then controlled probe, analyze, read, dump, write/erase and recovery actions when the bus is stuck.

Troubleshooting common symptoms

Common problems with I2C EEPROM chip

I2C EEPROM problems usually come from pull-ups, address pins, chip size assumptions, voltage or a stuck SDA/SCL line.

No address

Check pull-ups, voltage, SDA/SCL order, address pins and ground.

Reads wrap around

The chip may use a different addressing width or size than expected.

Bus stuck low

Disconnect targets one by one and use I2C recovery flows.

FAQ module-specific answers

I2C EEPROM chip FAQ

Quick answers about I2C EEPROM addresses, pull-ups, bus recovery, dumps and safe byte writes.

Can ESP32 Bit Pirate dump I2C EEPROMs?

Yes. Scan the bus first, then use the dedicated eeprom shell to probe, analyze, read bytes or dump the EEPROM.

Why does the scan show multiple addresses?

Some EEPROMs use address pins or banked addressing that expose multiple 7-bit addresses.

Should I write to EEPROM immediately?

No. Use the EEPROM shell to probe the chip and create a backup first, then write only when you know the chip and page layout.

Can it recover a stuck I2C bus?

Yes, use the I2C recovery action when a device holds the bus.

Which protocol page should I read?

Use the I2C protocol page for bus-level details.
